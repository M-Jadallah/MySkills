# مواصفة خطط القرآن التراكمية

## طلب كامل

```json
{
  "student_name": "محمد أحمد",
  "cumulative_pages": 5,
  "segments": [
    {"type": "surah", "name": "مريم"},
    {"type": "surah", "name": "طه"},
    {"type": "juz_range", "from": 28, "to": 30},
    {"type": "surah", "name": "البقرة"},
    {"type": "surah", "name": "الأنعام"},
    {"type": "surah", "name": "التوبة"}
  ]
}
```

يُنتج هذا الطلب ٢٠٦ عناصر: ١٧٣ عنصر صفحة، و٢٤ تراكميًا، و٩ اختبارات بشهادات. يتكرر رقم الصفحة ٣١٢ لاشتراك مريم وطه فيها. تكون جميع خلايا `id` فارغة، و`sort_order` من 1 إلى 206.

## أنواع النطاقات

| type | الحقول | المعنى |
|---|---|---|
| surah | name أو number | سورة كاملة |
| surah_range | from وto، اسمان أو رقمان | السور بين الطرفين، شاملًا الطرفين |
| juz | number | جزء كامل |
| juz_range | from وto | الأجزاء بين الطرفين |
| pages / page_range | from وto | نطاق صفحات شامل الطرفين |
| pages | numbers: [10,11,12,...] | تُجمع الصفحات المتجاورة في نطاقات مستقلة |

تحوَّل الأرقام العربية الشرقية والغربية إلى أعداد. يُطبّع اسم السورة للتشكيل والهمزات والتاء المربوطة، وتُحذف الوحدات المتكررة تمامًا. كلمة «جزء عم»=30، و«تبارك»=29، و«قد سمع»=28؛ يحوّلها الوكيل إلى أرقام في JSON.

الصفحات المجردة التي لا تطابق سورة أو جزءًا كاملًا تُعامل كوحدة مراجعة مستقلة، بتراكمي من أول نطاقها؛ لا يصدر عنها تسميع كامل أو شهادة لمجرد احتوائها جزءًا من سورة. إن طابق النطاق حدود وحدة كاملة واحدة، يستخدم تسميعها وأوزانها. إذا قصد المستخدم تجزئة نطاق الصفحات على حدود الأجزاء أو السور، أنشئ segments مستقلة بتلك الحدود ضمن الصفحات التي طلبها فقط.

لأعداد مختلفة على المستويات:

```json
"cumulative_pages": {"surah": 5, "juz": 7, "pages": 5}
```

يمكن استخدام مفتاح `default` لتغطية المستويات غير المحددة.

## التراكمي والبواقي

تقرأ الدفعة N صفحات جديدة، كل منها صف مستقل، ثم صف تراكمي واحد يغطي **كل الصفحات التي قرئت من الوحدة**. لا يعاد التراكمي بعد كل صفحة، ولا يعاد ضبط بدايته عند الدفعة التالية. بقاء الصفحات منفردة لا يعني التراكمي بعد كل صفحة.

عند الباقي: 13 صفحة وN=5 تصبح دفعتين 5+8. و23 صفحة تصبح 5+5+5+8؛ فلا تضع مراجعة عند الصفحة العشرين ثم دفعة من ثلاث صفحات. توجد مراجعة بعد الدفعة الأخيرة فقط إذا لم يوجد تسميع كامل للسورة أو الجزء بعدها. التسميع الكامل يحتفظ بوزنه الأصلي حتى لو احتوى اسمه على كلمة «تراكمي»؛ صفر الوزن مخصص لنطاق الصفحات العددي فقط.

السورة أو الجزء هما وحدة التراكم؛ السور المتفرقة مستقلة. عند اختيار الأجزاء الثلاثة الكاملة من مجموعة معيارية 1+2+3 أو4+5+6 ... أو28+29+30، يضاف تسميع الثلاثة بعد اكتمالها، ببياناتها الأصلية عند وجودها. لا يصدر عن مجرد صفحات جزئية تسميع ثلاثة أجزاء أو شهادة.

الجزء 16 يبدأ بصفحة 302 ويعبر نقطة بدء الخطة 305. عند اختياره كاملًا ترتب صفحاته 305–321 ثم302–304، وتؤجل شهادته حتى اكتمالها. كل تراكمي يقتصر على الصفحات المقروءة فعلًا؛ إن عبر نطاق جزئي نقطة الدوران يكتب بمديين، مثل `(305 - 310) + (300 - 304)`، ولا يضم الصفحات الواقعة خارج الطلب.

## تعارضات تتطلب قرارًا عند وقوعها

- `too_short`: الوحدة أصغر من N، فلا يمكن الالتزام بالحجم دون إضافة صفحات غير مطلوبة. اطلب تقليل N أو السماح بالوحدة القصيرة. بعد موافقة المستخدم على الاستثناء فقط، أضف `"allow_short_units": true`؛ لا تفعّله افتراضيًا.
- `overlap`: وحدة داخلة في وحدة أخرى أو تداخل واسع. اطلب هل يقصد المراجعة المستقلة مرتين أم اختيار نطاق واحد. للمراجعة المستقلة الصريحة استخدم `"overlap_policy": "independent"`. إذا أراد نطاقًا واحدًا صحح segments لإزالة التكرار قبل البناء. يسمح تلقائيًا بصفحة الحد المشتركة بين السور المسمّاة، حتى لو اجتمعت عدة سور قصيرة على الصفحة نفسها؛ وترتب السور داخل الصفحة بترتيب المصحف.
- اسم أو عدد أو نطاق غير صالح: وضّح القيمة المحددة فقط. لا تخمّن اسمًا ملتبسًا.

## القالب وحقول الشهادة

ورقة واحدة باسم القالب الأصلي `Worksheet`، بهذه الأعمدة الحرفية:

| العمود | العنوان | قاعدة البيانات |
|---|---|---|
| A | id | خالٍ من القيم والصيغ في كل صف بيانات |
| B | sort_order | 1..N متصل |
| C | خطة التسميع | رقم صفحة، أو نطاق تراكمي، أو تسميع كامل |
| D | النقاط | من المصدر للصفحات والاختبارات؛ التراكمي الجديد 20 |
| E | الوزن | صفحة=1؛ نطاق تراكمي=0؛ اختبار=وزنه المحفوظ |
| F | منفرد | يُحفظ من اختبار الأصل |
| G | أخذ الشهادة | 1 عند اختبار مؤهل للشهادة |
| H | اسم السورة | بيانات شهادة السورة |
| I | اسم الجزء | بيانات شهادة الجزء |
| J | رقم الثلاث أجزاء | بيانات شهادة الثلاثة |
| K | اسم الكتاب (السُنّة) | محفوظ في القالب وفارغ لهذه الخطط |

الأصل يعرّف أوزان 56 سورة و20 جزءًا و7 مجموعات ثلاثة أجزاء. تحفظها الأداة حرفيًا. السورة غير المسجّلة وزنها 1 بموافقة المستخدم؛ تترك نقاط اختبارها فارغة لعدم وجود مرجع، ويذكر ذلك في الرد. الأجزاء الجديدة وزنها 2 ونقاطها 400 وفق النمط الغالب في الأصل، والثلاثة الجديدة وزنها 3 ونقاطها 600. يمكن أن يحدد المستخدم نقاطًا أو وزنًا بدل تلك القيم عبر:

```json
"test_overrides": {"surah:107": {"points": 30, "weight": 1}}
```

## التوليد والتحقق

`scripts/planner.py` ينتج الصفوف دون كتابة Excel. `scripts/build_plan.py` يشغّل `scripts/render_workbook.mjs` باستخدام Artifact Tool من runtime المجمعة، ثم يعيد خصائص RTL الأصلية ويزيل سجلات الصفوف الفارغة الزائدة من OOXML؛ فالمكتبة لا تحفظ RTL عند التصدير. لا يستخدم openpyxl أو xlsxwriter للكتابة. تتحقق الأداة من بيانات الملف المصدر فعليًا، والقالب، والخانات الفارغة، والترتيب والتغطية، وتنتج معاينات PNG.

قد ينهي محرك المعاينة في Windows العملية برمز غير صفري بعد كتابة الصور وإيصال اكتمال جديد. تعتمد الأداة نجاح المعاينة على الإيصال الجديد وصلاحية ملفات PNG، ونجاح الملف على فحص XLSX المستقل؛ وتسجل رمز المحرك في تقرير العمل للتشخيص. تعرض هذه المعاينة الأعمدة LTR أحيانًا، بينما اتجاه Excel محفوظ RTL. افحص وضوح المعاينة واتجاه الورقة المخزن كلًا منهما على حدة.

شغّلها باستخدام Python وNode وnode_modules التي يعيدها `load_workspace_dependencies`. لا تثبّت حزمًا في مجلد التبعيات. تنشأ وصلة node_modules داخل WORK_DIR. تستخدم الأداة الملفات الأصلية داخل assets للقراءة فقط. لا تُعدّل أو تُحذف ملفات الطالب السابقة؛ أنشئ مجلد إخراج جديدًا عند تكرار الاسم، أو استخدم `--overwrite` إذا طلب المستخدم تعديل الملف الموجود صراحةً.

## مصادر البيانات

- `assets/plan-template.xlsx`: نسخة القالب الذي قدمه المستخدم؛ جميع الأعمدة والعروض ودلالات النقاط والأوزان مأخوذة منه.
- `assets/catalog.json`: بيانات الـ114 سورة والـ30 جزءًا وصفحاتها، وأوزان الاختبارات ونقاط الصفحات المستخرجة من القالب. تتضمن بصمات SHA256 وتاريخ التحقق.
- فهرسة مصحف المدينة برواية حفص: [Tanzil Quran Metadata](https://tanzil.net/docs/quran_metadata)، و[البيانات الأصلية](https://tanzil.net/res/text/metadata/quran-data.xml). لا يلزم تحميلها مجددًا أثناء التوليد العادي.
