# مصنع خطط الحفظ (quran-plan-factory)

## نظرة عامة (Overview)
هذه المهارة تنتج **خطط حفظ مخصصة** مقتطعة من الخطة المنهجية الأم (ملف
`الخطة المنهجية - المصححة.xlsx`). المستخدم يطلب مدى معيّناً — أجزاء أو سوراً أو
خليطاً مبعثراً منهما — فتحلل المهارة الطلب، وتستخرج الأيام المعنية من اللقطة
المجمّدة للخطة الأم، وترتبها بترتيب الخطة الأم نفسه، وتولّد ملف Excel جديداً
منسقاً يتضمن ورقة الخطة الكاملة وورقة ملخص.

## القاعدة الصارمة (Hard Rules)
1. **لا تعدّل الخطة الأم أبداً** (`الخطة المنهجية - المصححة.xlsx`) ولا ملف اللقطة
   `assets/master_plan.csv` — كلاهما مصدر قراءة فقط.
2. المخرجات دائماً **ملف جديد** لا يمس المصدر.
3. لا تُخترع أيام أو صفوفاً غير موجودة في الخطة الأم؛ كل ما في الخطة المخصصة
   منقول حرفياً (خطة التسميع، النقاط، الوزن، منفرد).

## بنية الملف الناتج
ورقة «الخطة المخصصة» تحمل 10 أعمدة فقط بهذا الترتيب:

| العمود | المحتوى |
|---|---|
| `id` | فارغ تماماً (حقل مخصص للتعبئة لاحقاً) |
| `sort_order` | الترقيم الجديد المتصل 1..N |
| `خطة التسميع` | بند اليوم كما في الخطة الأم |
| `النقاط` | نقاط اليوم كما في الأم |
| `الوزن` | وزن اليوم كما في الأم |
| `منفرد` | علامة المحطات الكبرى كما في الأم |
| `أخذ الشهادة`، `اسم السورة`، `اسم الجزء`، `رقم الثلاث أجزاء` | فارغة (كما في الأم) |

أعمدة الجزء والسور **لا تُكتب في الملف الناتج** — تُستخدم داخلياً فقط لتحديد
نطاق الاستخراج من الخطة الأم، وتظهر معلوماتها في ورقة «الملخص» ضمن أوصاف
المقاطع. ورقة «الملخص» تعرض: المقاطع كما حُلّت، الصفحات المشمولة، توزيع
الأيام (حفظ/دوري/مراجعات/شهادات)، قائمة الشهادات بنقاطها، ومجموع النقاط
الخام والموزونة.

## التبعيات (Dependencies)
- Python 3 مع مكتبة `openpyxl` (مثبتة في بيئة المستخدم).

## مصادر المهارة
| الملف | الدور |
|---|---|
| `scripts/build_plan.py` | سكريبت الاستخراج والتوليد (lookup / build) |
| `assets/master_plan.csv` | لقطة مجمّدة للخطة الأم (1074 يوماً × 13 عموداً) |
| `assets/reference.md` | دلالات الخطة الأم (الإيقاعات، النقاط والأوزان، الشهادات) |

## خطوات العمل (Workflow)

### 1. تحليل طلب المستخدم إلى مواصفة JSON
استمع لطلب المستخدم الحر وحوّله إلى مواصفة منظمة. أنواع المقاطع الأربعة:

| النوع | الاستخدام | مثال |
|---|---|---|
| `surah` | سورة مفردة | «سورة النمل» |
| `surah_range` | مدى من سورة إلى سورة (يشمل كل السور البينية) | «من سورة مريم حتى سورة الأنبياء» |
| `juz` | جزء مفرد | «الجزء التاسع» |
| `juz_range` | مدى من جزء إلى جزء (يشمل الأجزاء البينية) | «من الجزء 27 إلى الجزء 28» |

القواعد:
- «من كذا حتى كذا» = مدى (`surah_range` / `juz_range`)؛ أما السرد المتعدد
  («جزء 27 و28»، «الجزء التاسع والعاشر والحادي عشر») = مقاطع مفردة متتالية.
- حوّل الأرقام المكتوبة كتابةً («التاسع» = 9) والأرقام المشرقية (٩ = 9).
- ادمج التكرار: إن ذُكر العنصر مرتين يكفي مقطع واحد.
- لا تفترض ترتيباً ذهنياً: الخطة الأم هي المرجع، والمقاطع المتفرقة تُرتَّب تلقائياً.

نموذج المواصفة (احفظه مؤقتاً مثلاً في `plan_spec.json` بمجلد العمل):

```json
{
  "segments": [
    {"type": "surah_range", "from": "مريم", "to": "الأنبياء"},
    {"type": "surah", "name": "النمل"},
    {"type": "juz_range", "from": 27, "to": 28},
    {"type": "surah", "name": "آل عمران"},
    {"type": "juz", "number": 9},
    {"type": "juz", "number": 10},
    {"type": "juz", "number": 11},
    {"type": "surah", "name": "الإسراء"}
  ]
}
```

### 2. التحقق من الأسماء (عند الشك)
إذا كان اسم سورة في الطلب غير واضح أو مكتوباً بصيغة غير مألوفة، اعرض الفهرس
أولاً للتأكد (التطبيع يتكامل مع الفروق الإملائية الشائعة: الهمزات، التاء
المربوطة، التشكيل):

```bash
python "C:/Users/asala/.agents/skills/quran-plan-factory/scripts/build_plan.py" lookup
```

إن لم يتطابق الاسم مع أي سورة، سيقترح السكريبت أقرب الأسماء تلقائياً — استخدمها
للتصحيح، واسأل المستخدم فقط عند اللبس الحقيقي (سورتان محتملتان).

### 3. البناء

```bash
python "C:/Users/asala/.agents/skills/quran-plan-factory/scripts/build_plan.py" \
  build --spec plan_spec.json \
  --out "خطة مخصصة - <وصف مختصر>.xlsx"
```

احذف ملف `plan_spec.json` المؤقت بعد نجاح البناء.

### 4. التسليم
السكريبت يطبع ملخصاً (عدد الأيام، الصفحات، الأنواع، النقاط الخام والموزونة)
ويتحقق ذاتياً من سلامة الترقيم والتغطية قبل الكتابة. انقل الملخص للمستخدم مع
مسار الملف، وأشر إلى ورقة «الملخص» داخل الملف التي تفصّل: المقاطع كما حُلّت،
الصفحات المشمولة، توزيع الأيام (حفظ/دوري/مراجعات/شهادات)، قائمة الشهادات
بنقاطها، وأي شهادات ممتدة أُدرجت لوقوعها ضمن النطاق.

## دلالات الاستخراج (ما الذي سيحصل عليه المستخدم)
- **سورة مفردة**: امتدادها المتصل في الخطة + شهادتها الخاصة (مثل «سورة النمل
  تراكمي»)، وشهادات الأجزاء المضمّنة داخل امتدادها تبقى كما في الأم.
- **مدى سور**: كل السور بين الطرفين بالترتيب، بكل صفوفها كما في الأم حرفياً.
- **جزء/مدى أجزاء**: كل الصفوف المخصصة للجزء في الخطة الأم حرفياً.
- المقاطع المتفرقة تُدمج وتُرتَّب حسب ترتيب الخطة الأم ويعاد ترقيمها 1..N
  دون أي عمود إضافي.
- الشهادات الممتدة (مثل «(16+17+18)» أو «تسميع جزء عمّ + جزء تبارك + قد سمع»)
  إن وقعت ضمن النطاق تُدرج كما في الأم ويُشار إليها في الملخص.

## معالجة الأخطاء (Self-Correction)
1. عند فشل البناء اقرأ رسالة الخطأ بدقة: أسماء غير معروفة → صحّح المواصفة من
   مخرجات `lookup`؛ جزء غير موجود → الأجزاء الصحيحة 1–30.
2. عند شكوك في دلالة الطلب (مثلاً «من النور إلى الكهف» حين يكون المقصود غير
   واضح) اسأل المستخدم قبل البناء بدلاً من التخمين.
3. أي خطأ متكرر في السكريبت نفسه: أصلحه في `build_plan.py` جذرياً وأعد التشغيل.
