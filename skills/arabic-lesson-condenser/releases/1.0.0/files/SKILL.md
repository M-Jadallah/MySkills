# التكثيف الأقصى للدروس الإسلامية (arabic-lesson-condenser)

## نظرة عامة (Overview)

تحوّل هذه المهارة ملف تفريغ درس إسلامي إلى **خلاصة مكثفة** في ملف Word — وهو مستوى اختزال أعلى من الصياغة العادية:

- **تخطي التفاصيل بثقة**: الشروح الممتدة، التقرير بإعادة القول، التكرار، الأمثلة العارضة، الانتقالات الشفهية — كلها تُتخطى كليًا لا تُختصر فقط.
- **جُمَل مكتظة**: كل جملة تحمل أقصى معلومة ممكنة (دمج + قيود قصيرة بدل جمل مستقلة) — لا جملة لأسلوب.
- **صفر تضييع جوهري**: كل معلومة جوهرية أو مهمة تُحفظ حتمًا — تعريفات، أحكام، فروق، قيود واستثناءات، أدلة، أسماء وكنى ونسب وتواريخ، أعداد، تصنيفات، فوايد ذكرها الشارح، أمثلة بُني عليها حكم.
- **الأدلة استثناء كامل**: الآيات والأحاديث والنقول تُنقل نصًا كاملة بتشكيلها في بلوك مميز (تظليل أخضر فاتح ونص أخضر غامق) — لا تدخل في الاختصار أبدًا.
- **الجدول والخريطة عند الحاجة**: وهما أداتا تكثيف طبيعيتان للتصنيفات والمقارنات وفروع الفكرة المركزية.
- **تنسيق Word مثبت**: Traditional Arabic 22pt، RTL، عناوين حمراء قابلة للطي (Heading 1–4)، أقواس وتنصيص بالبني تلقائيًا، جداول مظللة، خرائط مفاهيمية SmartArt حقيقية قابلة للتحرير.

**الفرق عن الشقيقتين**: `arabic-lesson-formatter` تنسّق التفريغ كما هو؛ `arabic-lesson-rewriter` تعيد الصياغة بجُمَل علمية سياقية مختصرة؛ وهذه المهارة تُخرج **خلاصة مكثفة بأقصى اختزال ممكن دون أي تضييع جوهري**.

الصياغة بيدك أنت (الوكيل) — لا نداءات API ولا مفاتيح. السكربتات تتحقق من إخراجك ثم تولّد Word وتفحصه.

## التبعيات (Dependencies)

- Python 3.10+ و`python-docx>=1.1.2` (ملف `requirements.txt`). تحقق بـ: `python -c "import docx"`.
- لا تبعيات أخرى — لا شبكة، لا مفاتيح API.
- **مسارات التنفيذ**: السكربتات مستقلة عن مجلد العمل الحالي؛ نُفِّذها بمسارها الكامل من أي مكان — مثل `python C:/Users/asala/.agents/skills/arabic-lesson-condenser/scripts/build_docx.py ...` — مع إعطاء مسارات المدخلات/المخرجات مطلقةً أو نسبيةً لمجلد عملك.

## خطوات العمل (Workflow)

### 1. الكشف وتحديد الملفات

- إن أعطاك المستخدم مسار ملف أو ملفات أو نصًا مباشرًا، فاستخدمه كما هو.
- وإلا فشغّل:

```bash
python scripts/orchestrator.py [المجلد-اختياري]
```

فينشئ `lessons_input/` و`lessons_output/` ويعيد JSON بقائمة ملفات `.txt` الجاهزة وأسماء المخرجات المقترحة.

- **ملف واحد**: عالجه أنت مباشرة بخطوات القسم 2.
- **عدة ملفات**: شغّل وكيلًا فرعيًا باسم `arabic-lesson-condenser-subagent` لكل ملف، تزوّده بمسار ملف واحد + مجلد المخرجات، وأمِرَه بتنفيذ خطوات القسم 2 كاملة (بما فيها قراءة المراجع). راقب تقدمهم حتى يكتملوا. عند أي تعارض في العمليات انتقل للتنفيذ **بالتوالي**. في النهاية قدّم تقريرًا: عدد الناجح، عدد الفاشل، وأسباب فشل كل ملف.

### 2. خطوات معالجة الملف الواحد (تنفذها أنت أو الوكيل الفرعي المعني بالملف)

**أ. القراءة والفهم**: اقرأ التفريغ كاملًا، واستوعب سياقه العلمي، وحدد محاوره الحقيقية، **وافصل ذهنيًا في كل موضع بين معلومة (تُحفظ) وشرح/تقرير (يُتخطى)**.

**ب. التكثيف**: أخرج خلاصة كل محور وفق **العقد الصياغي** أدناه. إن كانت أول مرة لك في هذه الجلسة — أو كنت وكيلًا فرعيًا — فاقرأ أولاً:
- `references/rewriting-rules.md` (مواصفة التكثيف الكاملة: اختبار المعلومة، تقنيات الاختزال، الخطوط الحمراء، أمثلة قبل/بعد).

**ج. كتابة الـ JSON الوسيط**: اكتب ملف `lesson.json` مؤقتًا وفق المخطط الحرفي في `references/lesson-schema.md`. كل نص فيه **مشكَّل تشكيلًا كاملًا**.

**د. التحقق المسبق**:

```bash
python scripts/validate_input.py --input lesson.json
```

- `ok: true` → انتقل للخطوة هـ.
- `ok: false` → أصلح كل خطأ في الـ JSON وأعد الفحص. **لا تتجاوز الأخطاء أبدًا**.
- التحذيرات (أرقام إنجليزية، عبارة الصلاة الكاملة، تنوين خاطئ) لا تمنع البناء — البناء يصلحها تلقائيًا — لكن الأفضل إخراج JSON نظيفًا من البداية.

**هـ. البناء والفحص النهائي**:

```bash
python scripts/build_docx.py --input lesson.json --output lessons_output/<اسم-الدرس>.docx
```

سكربت واحد يعيد التحقق، ثم يبني الملف (مع خرائط SmartArt)، ثم يفحص الملف الناتج هيكليًا، ويعيد تقرير JSON واحدًا.

**و. بوابة التسليم** (أدناه) ثم احذف `lesson.json` الوسيط.

## العقد الصياغي غير القابل للتجاوز (Non-negotiable Condensing Contract)

1. **تكثيف لا إعادة سرد**: المستند خلاصة كل موضوع، وليس صياغة مطولة للتفريغ. لا جملة لأسلوب أو تقرير أو إعادة قول — كل جملة تضيف معلومة جديدة.
2. **اختبار المعلومة قبل الكتابة**: كل معلومة في التفريغ إما **جوهرية/مهمة** (تعريف، حكم، فرق، قيد أو استثناء، دليل، اسم وكنية ونسب وتاريخ، عدد، تصنيف، فائدة لغوية أو بلاغية ذكرها الشارح، مثال بُني عليه الحكم) فتُحفظ حتمًا مضغوطة — وإما **شرحًا أو تقريرًا أو تمهيدًا أو انتقالًا** فتُتخطى. النُّحوة الجديدة داخل الشرح تُضغط قيدًا قصيرًا في جملة المعلومة الأم.
3. **تخطي التفاصيل بثقة**: لا تقلق من حذف الشرح الممتد والتكرار التقريري وملخصات المحاضر الداخلية — ما تحميه من معلومة إن وُجد سُجّل في جملة المعلومة الأم.
4. **أقصى اختزال للجملة**: ادمج الجمل المتكررة، واحذف الحشو والانتقالات، واستخدم القيد القصير بدل الجملة المستقلة — مع بقاء كل جملة مكتملة المعنى (لا نقاط غامضة بلا سياق).
5. **الأدلة استثناء كامل**: الآيات والأحاديث والنقول تُنقل **نصًا كاملة بتشكيلها** في بلوك `"evidence"` تحت الحكم الذي تثبته — لا تدخل في الاختصار أبدًا، ولا تُلخَّص ولا تُقص ولا تُستبدل ولا تُخترع. نقلة ناقصة أو مشوهة في التفريغ: تصحيح الخطأ الإملائي الواضح فقط أو تركها — لا إكمال من الذاكرة.
6. **الجدول والخريطة عند الحاجة فقط**: للتصنيفات والمقارنات والأركان ذات السمات المشتركة (جدول)، وللفكرة المركزية المتفرعة بترتيب الاستدلال (خريطة: عقدة 2–7 كلمات مشكولة). المحور السردي البسيط بلا جدول ولا خريطة.
7. **التشكيل الكامل** لكل نص، وﷺ بدل الصلاة الكاملة، وأرقام عربية ٠-٩. الأقواس `( )` و`[ ]` والتنصيص `« »` تُلوَّن بالبني تلقائيًا — استخدمها للاستدلالات وأرقام الآيات والمصادر.
8. **لا معرفة من خارج التفريغ**: لا أقوال ولا فوائد ولا شواهد تُضاف من عندك — التكثيف يعيد ضغط ما في التفريغ فقط.
9. **لا تسليم ناقص بصمت**: أي محور فشل تحققُه أو خرائطته يُعالَج قبل التسليم — ولا تحذف معلومة جوهرية لإنجاح الفحص أو تقصير النسبة.

## بوابة التسليم (Delivery Gate)

كل الشروط التالية يجب أن تمر قبل تسليم أي ملف — تقرير `build_docx.py` هو الحكم:

1. `ok: true` — أي `input_errors` فارغة (بنية + تشكيل) و`docx_errors` فارغة (سلامة الملف الناتج).
2. `smartart_failures: []` — عند فشل خريطة لمحور: **بسّط الخريطة** (قصّر عناوين العقد، قلّل الفروع أو العمق) وأعد البناء. لا تسلّم أبدًا ملفًا يحوي ملاحظة "⚠ تعذّر توليد الخريطة".
3. `section_count ≥ 1` وعدد المحاور يساوي ما خططت له من التفريغ — لا محور مفقود.
4. **مراجعة الاكتمال قبل التسليم**: افحص صياغتك سطرًا سطرًا مقابل التفريغ — أي معلومة من فئة الخطوط الحمراء (تعريف/حكم/فرق/قيد/دليل/اسم/تاريخ/عدد/تصنيف/فائدة) فاتتك، أضِفها مضغوطة. الاختصار اللامع الذي يضيّع جوهرًا رفضٌ لا إتقان.
5. `input_warnings` تُقبل فقط لأن البناء يصلحها تلقائيًا؛ وعلى الوكيل الطموح أن يُخرج JSON بلا تحذيرات من المحاولة الأولى.

## التعلم الذاتي وحل المشاكل (Self-Correction & Learning Rules)

عند أي فشل:

1. حلّل رسالة الخطأ بدقة (أخطاء التحقق تصف الحقل ومكانه بالضبط).
2. أصلح جذريًا: الخطأ في الـ JSON أصلحه في الـ JSON؛ وإن كان الخلل في السكربتات نفسها (`scripts/`) فعدّلها إصلاحًا جذريًا يجعلها أكثر مرونة وموثوقية لمنع تكرار الخطأ.
3. أعد التشغيل واستمر — ولا تضيّع جوهرًا ولا تتجاوز بوابة التسليم لإنجاح الفحص.
