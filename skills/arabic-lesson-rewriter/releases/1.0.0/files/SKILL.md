# إعادة الصياغة المحكمة للدروس الإسلامية (arabic-lesson-rewriter)

## نظرة عامة (Overview)

تحوّل هذه المهارة ملف تفريغ درس إسلامي (شفهي، مليئًا بالحشو) إلى **وثيقة مذاكرة مكتظمة** في ملف Word:

- **الجسم كله صياغة الوكيل**: إعادة كتابة علمية مختصرة تغطي كل معلومة ذات معنى، بما فيها التفاصيل العميقة والقيود والتعليلات، بترتيب ورودها. تُضغط الشروح الممتدة ويُحذف الحشو والتكرار الخالي من إضافة جديدة؛ ولا يُحتفظ بكلام المحاضر الحرفي إلا في الأدلة المنقولة.
- **الأدلة تُنقل كما هي**: كل آية وحديث ونقل يُكتب نصًا بتشكيله في بلوك مميز (تظليل أخضر فاتح ونص أخضر غامق)، لا يُلخَّص ولا يُستبدل ولا يُخترع.
- **الجدول والخريطة عند الحاجة فقط**: تُضاف لكل محور إذا كان محتواه يستدعيها (مقارنة/تصنيف/فكرة مركزية تتفرع)، وتُترك لمحور سردي بسيط.
- **عرض مريح للقراءة**: تُقسَّم الأفكار إلى فقرات واضحة، وتُستخدم النقاط للعناصر المتوازية والأرقام للخطوات أو المسائل المرتبة؛ مع تباعد وإزاحة مناسبة للقوائم، دون تحويل الشرح كله إلى تعداد.
- **تنسيق Word مثبت**: Traditional Arabic 22pt، اتجاه RTL، عناوين حمراء قابلة للطي (Heading 1–4)، أقواس وتنصيص بالبني تلقائيًا، جداول مظللة، خرائط مفاهيمية SmartArt حقيقية قابلة للتحرير (ليست صورًا).

الصياغة بيدك أنت (الوكيل) — لا توجد أي نداءات API خارجية ولا مفاتيح. السكربتات المرفقة تتحقق من إخراجك ثم تولّد ملف Word وتفحصه.

## التبعيات (Dependencies)

- Python 3.10+ و`python-docx>=1.1.2` (ملف `requirements.txt`). تحقق بـ: `python -c "import docx"`.
- لا تبعيات أخرى — لا شبكة، لا مفاتيح API.
- **مسارات التنفيذ**: السكربتات مستقلة عن مجلد العمل الحالي؛ نُفِّذها بمسارها الكامل من أي مكان — مثل `python C:/Users/asala/.agents/skills/arabic-lesson-rewriter/scripts/build_docx.py ...` — مع إعطاء مسارات المدخلات/المخرجات مطلقةً أو نسبيةً لمجلد عملك.

## خطوات العمل (Workflow)

### 1. الكشف وتحديد الملفات

- إن أعطاك المستخدم مسار ملف أو ملفات أو نصًا مباشرًا، فاستخدمه كما هو.
- وإلا فشغّل:

```bash
python scripts/orchestrator.py [المجلد-اختياري]
```

فينشئ `lessons_input/` و`lessons_output/` ويعيد JSON بقائمة ملفات `.txt` الجاهزة وأسماء المخرجات المقترحة.

- **ملف واحد**: عالجه أنت مباشرة بخطوات القسم 2.
- **عدة ملفات**: شغّل وكيلًا فرعيًا باسم `arabic-lesson-rewriter-subagent` لكل ملف، تزوّده بمسار ملف واحد + مجلد المخرجات، وأمِرَه بتنفيذ خطوات القسم 2 كاملة (بما فيها قراءة المراجع). راقب تقدمهم حتى يكتملوا. عند أي تعارض في العمليات انتقل للتنفيذ **بالتوالي**. في النهاية قدّم تقريرًا: عدد الناجح، عدد الفاشل، وأسباب فشل كل ملف.

### 2. خطوات معالجة الملف الواحد (تنفذها أنت أو الوكيل الفرعي المعني بالملف)

**أ. القراءة والفهم**: اقرأ التفريغ كاملًا، واستوعب سياقه العلمي، وحدد محاوره الحقيقية وترتيبها.

**ب. إعادة الصياغة**: أعد كتابة كل محور وفق **العقد الصياغي** أدناه. إن كانت أول مرة لك في هذه الجلسة — أو كنت وكيلًا فرعيًا — فاقرأ أولاً:
- `references/rewriting-rules.md` (مواصفة الصياغة والأدلة والجدول والخريطة بالتفصيل مع أمثلة).

**ج. كتابة الـ JSON الوسيط**: اكتب ملف `lesson.json` مؤقتًا وفق المخطط الحرفي في `references/lesson-schema.md`. كل نص فيه **مشكَّل تشكيلًا كاملًا**.

**د. التحقق المسبق**:

```bash
python scripts/validate_input.py --input lesson.json
```

- `ok: true` → انتقل للخطوة هـ.
- `ok: false` → أصلح كل خطأ في الـ JSON وأعد الفحص. **لا تتجاوز الأخطاء أبدًا**.
- التحذيرات (أرقام إنجليزية، عبارة الصلاة الكاملة، تنوين خاطئ) لا تمنع البناء — البناء يصلحها تلقائيًا — لكن الأفضل إخراج JSON نظيفًا من البداية.

**هـ. البناء والفحص النهائي**:

```bash
python scripts/build_docx.py --input lesson.json --output lessons_output/<اسم-الدرس>.docx
```

سكربت واحد يعيد التحقق، ثم يبني الملف (مع خرائط SmartArt)، ثم يفحص الملف الناتج هيكليًا، ويعيد تقرير JSON واحدًا.

**و. مراجعة الشمول والعرض**: قارِن الصياغة بالتفريغ محورًا محورًا، وتتبَّع كل معلومة ذات معنى — ولو وردت داخل شرح طويل أو مثال — وتأكد من ظهورها بصياغة موجزة في موضعها. راجع القيود والتعليلات والاستثناءات والفروق والتفاصيل الدقيقة والأدلة خاصةً. ثم راجع توزيع الفقرات والقوائم والعناوين في الملف الناتج؛ عالج أي كتلة نصية مرهقة أو تعداد غير واضح دون حذف معلومة. التحقق البرمجي لا يثبت شمول المعاني أو راحة القراءة؛ أصلح `lesson.json` أو التنسيق ثم أعد التحقق والبناء قبل التسليم.

**ز. بوابة التسليم** (أدناه) ثم احذف `lesson.json` الوسيط.

## العقد الصياغي غير القابل للتجاوز (Non-negotiable Rewriting Contract)

1. **صياغة لا نسخ**: نص كل فقرة من صياغتك المكتظمة المكتملة المعنى — ليس كلام المحاضر الحرفي، ولا سرد نقاط مجرد، ولا تحويل المحتوى إلى أسئلة.
2. **شمول بلا إسقاط**: كل معلومة ذات معنى تُذكر **بترتيب ورودها**، سواء أكانت فكرة رئيسية أم تفصيلًا عميقًا أو تعريفًا أو حكمًا أو قيدًا أو تعليلًا أو استثناءً أو فرقًا أو مسألة. من يقارن الصياغة بالتفريغ لا يجد معلومة جديدة المعنى مفقودة. لا حد ثابت لعدد الكلمات؛ يطول الناتج بقدر ما تقتضيه كثافة الدرس.
3. **اختصار محكم للعبارة لا للمعلومات**: احذف الحواشي الشفهية ("يعني"، "طيب"، "كما قلنا"...) والتكرار الذي لا يضيف معنى. اضغط الشروح والاستطرادات الطويلة في أقل جمل واضحة تحفظ جميع نتائجها وقيودها. احتفظ بالمثال إن أضاف حالة أو فرقًا أو قيدًا، واضغط الأمثلة المتكافئة التي لا تضيف معنى جديدًا دون إضاعة ما توضحه.
4. **الأدلة كما هي**: الآيات والأحاديث والآثار والنقول تُنقل **نصًا بتشكيلها** في بلوك `"evidence"` تحت الحكم الذي تثبته — لا تلخيص للأدلة ولا استبدال ولا إضافة من الذاكرة. إن كانت النقلة في التفريغ ناقصة أو مشوهة، فصحِّح الخطأ الإملائي الواضح فقط، وإلا فانقلها كما وردت؛ ولا تُكملها من عندك.
5. **الجدول عند الحاجة فقط**: لمقارنات أو تصنيفات أو أركان متعددة ذات سمات مشتركة. صفوفه بتسلسل المحتوى، وكل خلية مكتملة المعنى، ومتسق مع الصياغة. المحور السردي البسيط لا جدول فيه.
6. **الخريطة عند الحاجة فقط**: لمحور له فكرة مركزية واضحة تتفرع. الجذر = الفكرة المركزية كما تعرضها الصياغة، والفروع بترتيب الاستدلال (سبب←نتيجة، عام←خاص، دليل←حكم)، والعقدة 2–7 كلمات مشكولة.
7. **التشكيل الكامل** لكل نص، وﷺ بدل الصلاة الكاملة، وأرقام عربية ٠-٩. الأقواس `( )` و`[ ]` والتنصيص `« »` تُلوَّن بالبني تلقائيًا — استخدمها للاستدلالات وأرقام الآيات والمصادر.
8. **لا معرفة من خارج التفريغ**: لا أقوال ولا فوائد ولا شواهد تُضاف من عندك — الصياغة تعيد ترتيب وضغط ما في التفريغ فقط.
9. **لا تسليم ناقص بصمت**: أي محور فشل تحققُه أو خرائطته أو مراجعة شموله يُعالَج قبل التسليم — لا تتجاوز بوابة التسليم أبدًا ولا تحذف محتوى لإنجاح الفحص.
10. **تنظيم بصري بلا تكديس**: اجعل لكل فكرة أو مسألة فقرة مستقلة، ولا تجمع مسائل مختلفة في فقرة طويلة. استخدم `bullet_list` للعناصر المتوازية غير المرتبة و`numbered_list` للخطوات أو المسائل التي يهم ترتيبها، واترك الشرح المتصل في فقرات. لا تكتب رموز النقاط أو أرقام التعداد يدويًا داخل النص، ولا تجعل القائمة بديلًا عن الشرح اللازم.

## بوابة التسليم (Delivery Gate)

كل الشروط التالية يجب أن تمر قبل تسليم أي ملف — تقرير `build_docx.py` ومراجعة الشمول معًا هما الحكم:

1. `ok: true` — أي `input_errors` فارغة (بنية + تشكيل) و`docx_errors` فارغة (سلامة الملف الناتج).
2. `smartart_failures: []` — عند فشل خريطة لمحور: **بسّط الخريطة** (قصّر عناوين العقد، قلّل الفروع أو العمق) وأعد البناء. لا تسلّم أبدًا ملفًا يحوي ملاحظة "⚠ تعذّر توليد الخريطة".
3. `section_count ≥ 1` وعدد المحاور يساوي ما خططت له من التفريغ — لا محور مفقود.
4. `input_warnings` تُقبل فقط لأن البناء يصلحها تلقائيًا؛ وعلى الوكيل الطموح أن يُخرج JSON بلا تحذيرات من المحاولة الأولى.
5. مراجعة دلالية محورًا محورًا: كل معلومة ذات معنى في التفريغ ممثلة في الصياغة أو الدليل، ولا يبقى من المحذوف إلا حشو أو تكرار بلا إضافة. تقرير البناء لا يغني عن هذه المراجعة.
6. مراجعة بصرية للملف الناتج: الفقرات مفصولة بوضوح، وعناصر القوائم مصطفّة ومتباعدة، والعناوين والأدلة متميزة؛ لا توجد كتل نصية متصلة مرهقة أو تعداد مكرر يدويًا.

## التعلم الذاتي وحل المشاكل (Self-Correction & Learning Rules)

عند أي فشل:

1. حلّل رسالة الخطأ بدقة (أخطاء التحقق تصف الحقل ومكانه بالضبط).
2. أصلح جذريًا: الخطأ في الـ JSON أصلحه في الـ JSON؛ وإن كان الخلل في السكربتات نفسها (`scripts/`) فعدّلها إصلاحًا جذريًا يجعلها أكثر مرونة وموثوقية لمنع تكرار الخطأ.
3. أعد التشغيل واستمر — ولا تحذف محتوى ولا تتجاوز بوابة التسليم لإنجاح الفحص.

## بنية المهارة

```
SKILL.md                     هذه الوثيقة
requirements.txt             python-docx>=1.1.2
config/default.json          الثوابت المثبتة (خط، ألوان، عتبات تشكيل، حدود الخريطة)
scripts/orchestrator.py      كشف الملفات + إنشاء lessons_input/lessons_output
scripts/validate_input.py    فحص الـ JSON (بنية + تشكيل) — يمنع البناء عند الأخطاء
scripts/build_docx.py        تطبيع + تحقق + بناء + فحص الملف الناتج → تقرير JSON واحد
scripts/arabic_text.py       أدوات عربية (تشكيل، تنوين، ﷺ، أرقام)
scripts/lesson_docx/         محرك توليد Word + SmartArt (builder, styles, tables, smartart, validate)
references/rewriting-rules.md  مواصفة إعادة الصياغة الكاملة (اقرأها قبل أول صياغة)
references/lesson-schema.md    مخطط lesson.json الحرفي
tests/                       اختبارات المهارة (python -m pytest tests/ -q)
examples/                    مثال كامل: تفريغ → lesson.json → docx
```
