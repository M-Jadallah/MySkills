# مخطط المحتوى الداخلي

تكتب JSON بعد تحليل المصدر كاملًا وبعد التشكيل. النصوص في JSON نهائية وليست مسودات غير مضبوطة. انظر `assets/sample-lesson.json` لمثال قابل للبناء. لا تستخدم نصوص المثال في درس المستخدم.

## الهيكل

```json
{
  "title": "عُنْوَانُ الدَّرْسِ",
  "scope": "نِطَاقٌ مُوجَزٌ مِنَ الْمَصْدَرِ",
  "topics": [{"id": "t1", "title": "عُنْوَانُ الْمَوْضُوعِ", "blocks": []}],
  "summary": [{"id": "s1", "kind": "bullet", "text": "نَصٌّ مَشْكُولٌ"}],
  "coverage": {"units": [], "source_accounting": []}
}
```

المعرفات فريدة وتبدأ بحرف لاتيني وتحتوي حروفًا وأرقامًا و`_` و`-` فقط. لا تظهر للمستخدم. لكل موضوع تمثيل بصري واحد على الأقل، ويجوز فقرات ربط قصيرة أو نقل أو تنبيه علمي من المصدر. `scope` اختياري؛ لا تنشئ بيانات مدرس أو مذهب أو تاريخ من عندك.

## الكتل

شجرة `diagram` مع `kind: tree` أو `decision`:

```json
{"id":"map1","type":"diagram","kind":"tree","title":"الْخَرِيطَةُ الْمَفَاهِيمِيَّةُ","root":{"label":"الْأَصْلُ","children":[{"label":"الْفَرْعُ","relation":"يَنْقَسِمُ إِلَى","children":[{"label":"تَفْصِيلٌ"}]}]}}
```

الأبناء بالترتيب العربي من اليمين لليسار. `relation` اختياري يصف العلاقة من الأب لهذا الابن ويظهر كسطر ثانوي داخل عقدة SmartArt. لا حد لعدد مستويات JSON؛ تُقسم المخططات تلقائيًا. لا تضع معرفات داخل التسميات أو تحذف تسمية لتناسب مخططًا. يستحسن أن تكون التسمية قصيرة، ويمكن تفصيلها في تمثيل تالٍ مرتبط مع حفظ المعلومة. نوع diagram يُنشئ SmartArt أصليًا دائمًا؛ لا يدعم اختيار محرك أشكال يدوية.

`sequence` أو `cycle` يستخدمان `nodes` بدل `root`: قائمة `{"label":"..."}` بالترتيب، دون أبناء مخفيين. تعرض الدورة 2–6 عقد في حلقة؛ وما زاد تعرضه الأداة تسلسلًا طويلًا يعود آخره للأول، مع تكرار العقدة الأولى في النهاية. لا تقسم دورة واحدة إلى دورات جزئية مغلقة لم ينص عليها المصدر. ينقسم التسلسل الطويل مع تكرار عقدة وصل بين اللوحات. علاقات الدورة التفصيلية تمثل في جدول مصاحب، وعلاقات التسلسل لا تضاف للعقدة الأولى التي لا سابق لها.

جدول:

```json
{"id":"table1","type":"table","title":"جَدْوَلُ الْمُقَارَنَةِ","columns":["النَّوْعُ","الْمِثَالُ"],"widths":[1,2],"rows":[["اِسْمٌ","كِتَابٌ"]]}
```

ترتيب الأعمدة من اليمين لليسار. `widths` نسب إيجابية اختيارية بحسب طول المحتوى؛ عدد الخلايا متساوٍ. أنواع `paragraph` و`quote` و`note` تحتاج `id` و`text`، وعنوانًا اختياريًا؛ يجب أن يكون النص مستندًا للمصدر. note تنبيه علمي من الدرس لا ملاحظة تحريرية عن مشاكل التفريغ.

النص إما سلسلة أو مصفوفة مقاطع:

```json
[{"text":"قَاعِدَةٌ","bold":true},{"text":" وَشَرْحٌ مُوجَزٌ."}]
```

تدعم المقاطع `bold` و`italic` و`underline`. الخلاصة تدعم `heading` و`paragraph` و`bullet` و`number`؛ `restart: true` يبدأ تعدادًا جديدًا. لا تكتب رموز نقاط أو أرقامًا يدوية داخل النص؛ الأداة تنشئ قوائم Word حقيقية.

## سجل التغطية الداخلي

```json
{"units":[{"id":"u1","claim":"وصف داخلي للمعلومة","source_quotes":["مقطع حرفي من التفريغ"],"visual_refs":["map1"],"summary_refs":["s1"]}],"source_accounting":[{"start":0,"end":24,"kind":"scientific","units":["u1"]}]}
```

`source_quotes` حرفية من TXT بعد فك الترميز وتوحيد نهايات الأسطر إلى LF فقط؛ قد تكون غير مشكولة. `start` شامل و`end` غير شامل بفهرسة حروف Python في النص الموحد. غطّ كل حرف غير فراغ بمقاطع غير متداخلة. `scientific` و`repetition` تربطان بوحدات، و`filler` و`metadata` تحتاجان `reason` داخليًا. صنف الحشو بصدق؛ لا تستخدمه لإسقاط مادة علمية. اقرأ المصدر باستخدام `check_lesson.load_source` لتطابق فك BOM وتوحيد CRLF/CR مع الفهارس، مع الاحتفاظ بملف المصدر الأصلي دون تعديل.

يمكن أن تحتوي عدة وحدات على المقطع نفسه إذا جمع عدة حقائق، ويمكن لوحدة ربط أكثر من رسم أو بند خلاصة. المراجع يجب أن تشير لكتل بصرية وبنود خلاصة حقيقية. صحة الربط البرمجية لا تثبت الأمانة الدلالية: قارن المعلومة وقيودها بالمصدر وبالتمثيل وبالخلاصة، ثم أعد مسح المصدر لاكتشاف وحدات فات استخراجها.
