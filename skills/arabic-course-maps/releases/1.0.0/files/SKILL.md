# خرائط الدروس المترابطة

حوّل مجموعة تفريغات لموضوع علمي واحد إلى **ملف Word واحد مترابط**. وحدة التحليل تفريغ واحد، ووحدة التأليف الموضوع كله. أنجز القرارات العلمية والتنظيمية والتصميمية دون الرجوع للمستخدم؛ لا تنشئ قسم «مواضع تحتاج مراجعة». عند استدعاء هذه المهارة على ملف واحد استخدم المسار نفسه بوكيل فرعي واحد. تبقى مهارة `arabic-lesson-maps` مستقلة؛ هذه الحزمة مكتفية بذاتها.

## ثوابت المخرج

- ابدأ من `assets/lesson-template.docx` عبر `scripts/build_course.py`. القالب والهوية ثابتان بين الملفات؛ المرجع `assets/design-tokens.json`: A4 عمودي RTL، Traditional Arabic في كل النصوص والخرائط، كحلي `#17324D` وبترولي `#247C78` وذهبي `#B58A35`، إطار مزدوج معتمد وخلفية بيضاء. لا تغير التصميم لكل مجموعة.
- **SmartArt أصلي قابل للتحرير إلزامي لكل خريطة**، مع نموذج البيانات والتخطيط والنمط والألوان والرسم الأصلي. لا تستخدم مجموعات أشكال أو VML أو صورة أو SVG بدلًا منه. الجداول جداول Word حقيقية.
- جميع النصوص العربية الظاهرة مشكولة تشكيلًا كاملًا ودقيقًا، بما فيها العناوين والعلاقات والخلايا وأواخر الكلمات والإحالات. الشواهد الداخلية حرفية ولا تُشكّل من عندك. التشكيل النهائي يأتي بعد استقرار الدمج ويُراجع لغويًا، ولا تثبته أعداد الحركات.
- لا حد لعمق التفرع المنطقي. توزع الخرائط الكبيرة على مخططات أصلية مترابطة بدل حذف معلومات أو تصغير النص. اختر الرسم بحسب العلاقة، ولا تفرض جدولًا وخريطة لكل موضوع.
- خريطة عامة أولًا، ثم موضوعات علمية بخرائط تفصيلية وجداول وإحالات داخلية، ثم **خلاصة واحدة شاملة مختزلة** في النهاية تبدأ صفحة جديدة. لا تنظم الملف كتجميع متتابع لملخصات الدروس.

## سير العمل

### ١ — المصادر والوكلاء

اقرأ [تنسيق التشغيل](references/orchestration.md) و[الأمانة والتشكيل](references/fidelity-and-vocalization.md). استخدم Python المحمّل من اعتماديات البيئة. المسارات في الأوامر نسبةً إلى جذر المهارة، ومسار run جديد داخل مجلد العمل:

```text
python scripts/prepare_course.py --inputs lesson-1.txt lesson-2.txt lesson-3.txt --work-dir work/course-run
```

بديل الإدخال `--input-dir transcripts` يرتب الملفات طبيعيًا. يحفظ الإعداد أصول الملفات وبصماتها ونسخها الموحدة وmanifest وjobs؛ لا يشغّل نماذج ذكاء اصطناعي بذاته.

**استدعِ وكلاء فرعيين حقيقيين: وكيل مستقل لكل تفريغ**، بدفعات ضمن حد التزامن. أعط كل وكيل job الخاص به و[عقد الوكيل](references/worker-protocol.md) ومسار JSON منفصلًا. يقرأ المصدر كاملًا ويستخرج الوحدات العلمية والأدلة والمفاهيم والعلاقات والإحالات والتصحيحات وسجل تغطية المصدر. لا يكتب Word ولا يطلع على تحليلات الآخرين. لا تستخدم create_thread لإنشاء محادثات مستخدم جديدة. لا تبدأ الدمج النهائي قبل اكتمال الجميع وقراءة ملفاتهم الفعلية.

```text
python scripts/check_course.py --manifest work/course-run/manifest.json --report work/workers-check.json
```

أعد الأخطاء للوكيل المسؤول، ثم أعد الفحص. غياب وكيل أو إخفاقه ليس مبررًا لإسقاط تفريغه. إذا غابت أدوات الوكلاء كليًا فاذكر العائق التقني بصدق ولا تدّعِ تنفيذ توزيع لم يحدث.

### ٢ — التأليف والدمج

اقرأ [مخطط الدمج](references/integration-schema.md). راجع كل تحليل مقابل المصدر، وأنشئ `course.json` مركزيًا: مفاهيم موحدة، وحقائق جامعة مرتبطة بجميع الوحدات الأصلية، وقرارات صريحة للعلاقات والإحالات والتصحيحات. احتفظ بالإضافة والشرط والاستثناء ونسبة الأقوال والخلاف والأمثلة المهمة. لا تستنتج التصحيح من كون الدرس أحدث؛ يلزم دليل صريح للعدول. لا تضف معرفة خارج المصادر أو تتمم نقلًا من الذاكرة.

ابنِ هيكل الموضوع كاملًا قبل اختيار الخرائط. أثبت العلاقات العابرة للدروس بالأدلة؛ لا تكتفِ بتشابه الألفاظ. ضع `concept_id` للعقد و`topic_ref` لفروع الخريطة العامة كما في المخطط. المترجم يضيف روابط Word داخلية للعامة والتفاصيل، لكنه **لا يستنتج الدمج العلمي ولا يختصر النص عنك**.

اقرأ [مخطط كتل الوثيقة](references/content-schema.md) و[العقد البصري](references/visual-contract.md) عند تأليف الخرائط والجداول والخلاصة. راجع كل النصوص الظاهرة والتشكيل بعد استقرار الدمج. الخلاصة تشمل كل معلومة متميزة؛ قوائم Word حقيقية للترتيب والتعداد والنقاط، مع تنسيق انتقائي يخدم الفهم.

### ٣ — البناء والفحص

```text
python scripts/check_course.py --manifest work/course-run/manifest.json --course work/course-run/course.json --report work/integration-check.json
python scripts/build_course.py --manifest work/course-run/manifest.json --course work/course-run/course.json --work-dir work/build --output outputs/course.docx
python scripts/check_course.py --manifest work/course-run/manifest.json --course work/course-run/course.json --docx outputs/course.docx --report work/document-check.json
powershell.exe -NoProfile -NonInteractive -STA -File scripts/verify_smartart_word.ps1 -InputDoc outputs/course.docx -ReportJson work/native-smartart.json
python scripts/render_lesson.py outputs/course.docx --output-dir work/render
```

يتطلب إنشاء SmartArt Microsoft Word على Windows وPowerShell STA، وPython 3.10+ مع python-docx وlxml وpypdf؛ ولصور الصفحات pypdfium2 أو pdf2image. يلزم Traditional Arabic مثبتًا، ولا توزّع ملفاته. تنفذ عملية Word مركزية واحدة؛ لا يشغّل الوكلاء Word بالتوازي. `--compile-only` في build_course يتيح فحص الترجمة دون إنشاء DOCX، ولا يحقق شرط تسليم Word.

يرفض الفحص مصدرًا متغيرًا أو عاملًا قديمًا أو وحدة ساقطة أو مفهومًا غير موحد أو قرار علاقة مفقودًا أو إحالة بلا هدف. يفحص أيضًا SmartArt وترتيب العقد والآباء والقالب والخط ومطابقة المحتوى عند تمرير DOCX. لا يثبت ذلك صحة الاستنتاج أو التشكيل: راجع دلاليًا من المصدر إلى المعلومات فالخرائط والخلاصة، وراجع المقاطع المصنفة حشوًا.

افتح **كل صفحة مرسومة** بالحجم الطبيعي، وافحص التفرعات وRTL والحركات والخط الفعلي والإطار والهوامش والجداول والإحالات والترقيم وعدم الاقتطاع. افحص تعرف Word على SmartArt. عند إحلال الخط في PDF استخدم مسار عرض متاحًا يحافظ عليه وتحقق منه؛ لا تعلن نجاح الفحص البصري لمجرد وجود PDF. لا تعِد حفظ المخرج عبر محول قد يفقد أجزاء SmartArt؛ التحويل للعرض نسخة فحص فقط. أعطال المحرك أو العرض تُذكر بأمانة ولا تُعالج باستبدال SmartArt بأشكال.

سلّم رابط Word النهائي وجملة قصيرة فقط. تبقى JSON والمصادر المنسوخة وسجلات التغطية وصور الفحص داخلية ما لم يطلبها المستخدم.

## الموارد التنفيذية

- `scripts/prepare_course.py`: حصر المصادر وترتيبها ونسخها وإعداد jobs.
- `scripts/course_model.py`: عقود التحليل والدمج والتحقق من التغطية وترجمة الأصل متعدد المصادر إلى الباني الثابت.
- `scripts/build_course.py`, `scripts/check_course.py`: مدخلا البناء والفحص للمسار المتعدد؛ لا تتجاوزهما ببناء lesson يدوي لإخفاء وحدات مفقودة.
- `scripts/build_lesson.py`, `smartart_backend.py`, `create_smartart.ps1`: محرك القالب وSmartArt الأصلي المضمّن، لا يتطلب المهارة القديمة.
- `scripts/verify_smartart_word.ps1`, `render_lesson.py`: تحقق Word وصور المراجعة.
- `assets/sample-course/`: مثال تحليلي متعدد المصادر مع دمج قابل للفحص والبناء؛ للاختبار فقط لا لمحتوى المستخدم.
- `scripts/test_pipeline.py --work-dir work/tests`: اختبارات التغطية والتصحيحات والبصمات والإحالات، دون نماذج أو Word.
- `assets/reference-preview.png`: مرجع الهوية السابق، والمقاسات والمواضع الحاكمة في القالب وثوابته.
